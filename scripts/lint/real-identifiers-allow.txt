# scripts/lint/real-identifiers-allow.txt — KYO-662
#
# Path exceptions for scripts/lint/check-real-identifiers.sh. Mirrors the
# shape and spirit of trivy-secret.yaml's allow-rules, but kept as its own
# file rather than a section of that one (binding decision in KYO-662: the
# two configs stay separate) because this linter's rule ids are its own and
# do not line up 1:1 with Trivy's secret-shape ids.
#
# Format: one entry per line, blank lines and `#`-prefixed lines ignored.
#
#     <rule-id>:<path-glob>:<justification>
#
# <path-glob> is matched, anchored at both ends, against the path exactly as
# scanned — repo-relative in full-tree/CI mode, whatever form was passed on
# the command line in pre-commit/explicit-path mode. `*` matches any run of
# characters, `?` matches exactly one. <justification> must be non-empty.
#
# This file exists ONLY for files that deliberately contain fake,
# structurally-real-looking material for tests — never for an actual
# customer identifier. If a real identifier needs an exception, that is not
# what this file is for: fix the source instead.
#
# No entry here needs a path glob wildcard today; every exception below is
# an exact, single-file path.

# GCP service-account test fixtures. Both already carry a trivy-secret.yaml
# allow-rule (Trivy's own secret-shape scanner also matches these), cited
# here by that rule's id so the two configs can be cross-checked by hand.
